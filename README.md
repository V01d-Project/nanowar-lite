# Nano War · 源码规则版

[直接玩](https://v01d-project.github.io/nanowar-lite/) · 无构建、无 npm 依赖的静态 Canvas 游戏。

按 Nano War 2 的反编译行为和数值重新实现；不分发原作代码、美术、音效、SWF 或反编译器。画面均为 Canvas 自绘。

## 操作

- 点选蓝色细胞，再点目标；也可直接拖到目标。
- 鼠标框选、触屏闭合圈选；A 全选、空格取消选择。
- 派兵按钮切换25/50/75/100%。普通兵先在母细胞内组装，再飞行，命中后分裂为逐兵结算的小兵。
- 特殊细胞送兵充能，脂肪读条9.6秒/抗体14.4秒（25fps）；**就绪后手动选择目标发射**，不再自动寻敌。
- 原版25关可切换；机制沙盒包含脂肪、抗体和 Normal AI，明确非原版关卡。
- 升级面板按通关获得的点数购买原版0–4级升级；点数和通关记录仅保留在当前页面会话，刷新后重置。

## 2–4 人在线对战：静态站 + 自选服务器

页面仍是**无构建、无 npm 依赖**的静态文件：GitHub Pages、任意静态端口、直接双击 `index.html`（file://）都能玩单人并连接独立联机服务。GitHub Pages 不负责运行模拟，玩家必须有一台所有人类玩家可达的服务器。

### 玩家连接

1. 点击右上「联机」，在「服务器地址」填 `https://你的服务器`，点「保存地址 / 检查连接」。支持 HTTP/HTTPS 和 WS/WSS 写法（WS 自动转为 HTTP，WSS 转为 HTTPS；实际传输为 HTTP JSON + SSE，不要求 WebSocket）。地址保存在 **localStorage**；留空默认页面同源的根地址。file:// 没有同源服务器，必须填写。
2. 玩家可从**不同网站/不同端口/本地文件**打开页面，但须填同一服务器地址。HTTPS Pages 应连接 HTTPS/WSS 服务，不能绕过浏览器混合内容限制。普通 HTTP 仅用于本地/局域网测试。
3. 房主先选总席位 **2/3/4**、AI 补位 **0–3**（至少保留一个人类席位）及 AI 难度 **easy / normal / noob**，再「创建房间」，其余人输入 **6 位房间码**加入。座位 side 1–4 分别为蓝、红、绿、黄；人类按可用座位加入，AI 从后向前填可用空位（也能填离房留下的中间空位，不挤掉现有人类），分别操作自己颜色。房主选竞技图及四项0–4级升级，保存会取消所有人类准备；不能用缩小人数或增加 AI 踢掉现有人类。面板始终显示「**公平模式：镜像地图 / 同等升级**」。所有人类在线且准备后房主才能开局（AI 自动准备）。
4. 断线后模拟暂停，席位保留 **30秒**，自动恢复 SSE/身份，原标签页刷新也能恢复；暂停期间 AI 也不行动。30秒过期或主动离房按弃权处理：该方细胞清零转中立、在途兵力移除；多人局其余阵营继续，最后存活阵营获胜。房主在战局中弃权后由下一位人类接任；准备阶段房主离开会关闭房间。所有建房、加入、事件流、指令、心跳、恢复请求均使用所选服务器。身份令牌存 **sessionStorage**，绑定服务器地址；入房期间锁定地址，离房后才能切换。不要复制已入房标签页的会话存储。
5. 所有仍在房间的人类同意重赛后回到准备阶段（AI 自动同意），可重新选人数 / AI 数量 / 难度 / 图 / 升级。离房返回单人。服务器不可达、服务类型错误、席位过期都会明确提示，不影响单人。

### 公平规则

- 2人使用三个**专用180°镜像竞技图**：镜像实验场（含成对相同脂肪/抗体）、镜像决斗（各一座60能量主基地）、镜像扩张（相同主基地与成对中立点）。不直接使用不对称战役关卡。2人沿用这些图；3/4人使用相同扇区按120°/90°旋转生成的规则多边形竞技图，地图在世界坐标中严格等距而非拉伸椭圆。所有阵营初始细胞数量、类型、尺寸、能量、充能状态完全对应；中立点也旋转对称。
- 房主升级**同时应用所有人类与 AI 阵营**；服务端强制 difficulty=0，即使旧客户端提交2也不会获得红方 ×1.5/×2 开局兵力，不读取战役敌方升级，无隐藏的人类/AI资源加成。AI 在服务端运行 `src/ai.js` 中原有 easy/normal/noob 模式，经同一 `Core.sendFleet` / `Core.step` 规则产兵战斗；难度只影响决策模式，不修改起始兵力或升级。面板明确显示总席位、当前人类、AI 数量与难度。
- 每局服务端生成一个种子并在面板公开；同房间所有人收到同一份25fps权威快照。客户端只提交指令，不执行本地联机模拟，不允许单方暂停、加速、重开、购买升级。
- 同一帧指令在边界统一处理，每方保持自己的指令顺序；2–4方处理优先级由种子选初值、逐帧循环轮转，单位/小兵处理也逐帧轮转，**没有固定房主/蓝方先手**或额外资源。实时对战仍受网络延迟影响，不承诺消除物理网络时延。
- PvP所有阵营使用相同的胜负条件：最后一方也要等待所有在途单位/小兵结算；同时无存活方记平局。战役的原始行为保持不变。

### 部署服务器 / CORS

Node.js 22+（本机Node24），无需 npm install：

    node server.js

默认监听 0.0.0.0:8080；PORT、HOST 可改。既可打开 http://localhost:8080/ 同源游玩，也可只用它提供API、让 Pages 提供静态页面。PowerShell 示例：

    $env:PORT='8080'; $env:HOST='0.0.0.0'; node server.js

- 公网部署建议在 Node 前放 HTTPS 反向代理；保留 /api/* 路由。若使用路径前缀如 https://host/nanowar，代理需把 /nanowar/api/* 去掉前缀转发为 /api/*，玩家地址填写该前缀根，不填 /api 或具体接口。
- 默认 **ALLOWED_ORIGINS=*（允许任意页面，包括 file:// 的 null origin）**。可选精确来源白名单，逗号分隔，不含路径或末尾斜杠，例如：

    $env:ALLOWED_ORIGINS='https://v01d-project.github.io,http://localhost:5500,null'; node server.js

- 白名单开启后同源页面也要将它的 origin 加入；file:// 需显式列入 null（表示所有不透明来源，不仅本地文件）。无 Origin 的命令行客户端仍可访问；CORS 不是身份认证，席位随机令牌才是授权依据。不同站点不发送/依赖Cookie。
- 所有 /api/* 包括错误响应、SSE 都提供 CORS 头，OPTIONS 返回204。SSE 使用 text/event-stream、no-cache/no-transform、X-Accel-Buffering:no 和心跳；**代理必须关闭缓冲/压缩聚合**，设置读取超时大于30秒。不要把 Node SSE 放到只支持静态文件的平台。
- 暴露公网时自行配置防火墙/HTTPS、代理限流；这是内存房间服务，无账号/持久化/多进程同步，重启会清空房间。不要公开席位令牌；代理访问日志应屏蔽事件流查询参数。

## 与旧 Lite 的关键差别

产兵间隔按固定地图尺寸(size)插值，不按当前能量；100是产兵软上限，增援可超过100；敌方脂肪罩还会使能量衰减；特殊细胞也计入胜负；抗体感染保留特殊电池能量。

**帧率说明：**模拟使用原始SWF的25fps，240/360帧对应9.6/14.4秒。完整数值、出处与历史对齐审计见[PORTING.md](PORTING.md)；本轮稳定性修复和批量模拟结果见[BUGSWEEP.md](BUGSWEEP.md)。

## 分层

- src/core.js：纯逻辑、固定25fps、种子随机、单位和mini碰撞；不接触DOM。
- src/levels.js：地图注册表和初始数据。
- src/ai.js：原版Normal优先级，只经公共派兵接口下单。
- src/render.js：只读Canvas；保持世界空间比例，窗口不会改变模拟数值。
- src/input.js：选取和Pointer适配。
- src/app.js：DOM、生命周期、计时器装配。
- src/arena.js：专用镜像竞技图与公平初始化（服务端）。
- src/net-client.js：联机传输、房间面板、标签页重连；通过 input/app 适配接口接入。
- server.js：静态白名单、房间生命周期、身份验证、权威 core 模拟和 SSE；无运行时依赖。

## 验证

    node tools/test-core.cjs
    node tools/test-browser.cjs
    node tools/test-net.cjs
    node tools/test-net-browser.cjs
    node tools/sim-sweep.cjs

核心84项零依赖测试；Chrome headless自动检查430×932、1280×800，包含全部25关和沙盒的布局、充能、封锁、触摸圈选、特殊手动发射，以及第一关可通关。共18张截图写入tools/shots/。离线sweep覆盖25关×3难度×4种AI配对，每局最多300秒游戏时间，完整JSON默认写入tmp/sim-sweep.json。Windows Chrome默认路径可用CHROME_PATH环境变量覆盖。

联机验收 `node tools/test-net.cjs` 先验证全部竞技图/升级镜像、种子确定性，再启动真实子进程以 HTTP/SSE 对战至判胜，检查越权/重放、快照一致、暂停/重连、重赛与真实30秒过期，以及CORS/预检/null来源。随后自动执行双Chrome跨域测试：两个不同端口的纯静态页连接同一服务器，断言开局资源/升级完全一致、打一局并重赛，验证红方操作、跨帧拖动、手动特殊发射、刷新恢复；再以真实file://页面连接/刷新，验证WS地址归一化、localStorage保存、不可达报错和白名单。浏览器端Core.step/sendFleet被替换为抛错函数，证明联机不调用本地模拟。新增 `tools/test-net-multi.cjs` 覆盖3/4个人类入座、side3/4指令与重连、2人类+2AI实际打完并重赛、多人局真实30秒弃权、三档AI与原有对应模式的确定性派兵回放一致性和所有图/升级旋转公平性。整套约3–5分钟，需已安装Chrome（CHROME_PATH可覆盖）；无需npm依赖。单独调试浏览器部分可运行 `node tools/test-net-browser.cjs`。
