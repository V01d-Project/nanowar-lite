# Nano War · 源码规则版

[直接玩](https://v01d-project.github.io/nanowar-lite/) · 无构建、无 npm 依赖的静态 Canvas 游戏。

按 Nano War 2 的反编译行为和数值重新实现；不分发原作代码、美术、音效、SWF 或反编译器。画面均为 Canvas 自绘。

## 操作

- 点选蓝色细胞，再点目标；也可直接拖到目标。
- 鼠标框选、触屏闭合圈选；A 全选、空格取消选择。
- 派兵按钮切换25/50/75/100%。普通兵先在母细胞内组装，再飞行，命中后分裂为逐兵结算的小兵。
- 特殊细胞送兵充能，脂肪读条9.6秒/抗体14.4秒（25fps）；**就绪后手动选择目标发射**，不再自动寻敌。
- 原版25关可切换；机制沙盒包含脂肪、抗体和 Normal AI，明确非原版关卡。
- 升级面板按通关获得的点数购买原版0–4级升级；点数和通关记录仅保留在当前页面会话，刷新后重置。

## 1v1 在线对战

需要 Node.js 22+（本机以 Node 24 验证），**不需要 npm install，不需要构建**：

    node server.js

打开 http://localhost:8080/，同一个端口同时提供页面和联机服务。同一局域网的另一台设备打开 http://服务器局域网IP:8080/（需防火墙允许）。可用环境变量 PORT / HOST 修改监听地址；默认 8080 / 0.0.0.0。仅本机测试可设 HOST=127.0.0.1。Windows PowerShell 例如：

    $env:PORT=8080; $env:HOST='127.0.0.1'; node server.js

1. 点击右上角「联机」→「创建房间」，把 **6 位房间码**发给另一位玩家。
2. 对方在**同一服务器网址**打开页面，输入房间码加入。玩家 1 是蓝方 side 1；玩家 2 是红方 side 2，红方选红色细胞操作。两页测试请独立开两个标签页，勿复制已入房标签页的会话存储。
3. 房主选择关卡（25 关或沙盒）、难度和四项 0–4 级升级，点击保存。**保存会取消双方准备**。准备面板向双方展示最终配置；双方准备后，由房主开局。
4. 点选、框选、圈选、拖动、A 全选和派兵比例与单人一致；就绪特殊细胞仍需手动发射。联机禁用暂停、倍速、单人升级和单方重开。
5. 断线后战局暂停，提示对手掉线，保留原席位 **30 秒**；自动重连，或在原标签页刷新恢复。身份令牌只放在当前标签页 sessionStorage，不放在房间码中。超过 30 秒判负，需离房重建；主动离房立即结束本局。后台网络失活会通过心跳检测，手机浏览器冻结页面也可能被视为掉线。
6. 本局结束后双方点击「请求重赛」，回到准备面板，可改配置，再准备并由房主开局。右上角房间按钮随时可打开面板、离房并返回单人。离房后单人从当前选择关卡重开，战役升级仍在页面会话内。

**地图说明：**联机无 AI；原地图的敌方 side 2/3/4（含脂肪归属）统一映射为红方 side 2。四项升级按房主配置**同时应用双方**，不使用战役内置敌人升级表。难度保留 core 原规则：进阶/专家只提高红方普通细胞开局兵力 ×1.5/×2。原版教学图、战役图不保证 1v1 公平（第一关蓝方优势明显）；普通难度沙盒更适合初次对战。两方具体开局可在保存后查看配置，游戏规则本身未修改。

### 部署 / GitHub Pages

- GitHub Pages 的纯静态版本**继续完整支持单人**，不能运行 Node 服务；在那里点击建房会明确提示需要联机服务器，不影响单人。联机需双方进入 Node 服务提供的网址，而非让静态页面跨域连接服务器。
- 将完整仓库放到支持常驻 Node 进程的机器，运行 node server.js；进程退出/重启会清空房间。按需要由你现有的进程管理方式托管。
- 公网建议通过 HTTPS 反向代理；现有 **nw.lagrange.top Cloudflare 隧道可以复用**，让其源站指向本进程实际端口即可。**本次没有改动或发布任何线上/隧道配置**。请勿同时启动另一个占用相同端口的服务。
- 代理需保留 Host、传递 X-Forwarded-Proto=https，允许长连接 SSE，关闭事件流缓冲/缓存（服务端已发送 no-cache、no-transform 和 X-Accel-Buffering:no）。不需要 WebSocket 升级，不需要开放额外端口。部署在站点根路径 /，目前不支持子路径挂载。
- 使用零依赖 **SSE + POST** 而不是手写 WebSocket：浏览器 POST 只发送配置/准备/选取/比例/派兵等指令；Node 直接调用未修改的 src/core.js，以固定 **25fps** 推演和广播完整权威快照。客户端联机时不执行 step、AI 或 sendFleet，也没有本地预测；两端读取同一 revision 的相同状态。慢客户端积压超过 1MiB 会断开并走重连。
- 无账号、匹配、观战、聊天、持久化、跨进程房间、回放或竞技平衡；没有全局公网防滥用系统。现有基础防护包括不可猜的席位令牌、同源校验、单席位 60 指令/秒、请求大小/时间限制、最多 100 房间、闲置回收和静态路径白名单。它适合邀请制小规模对战，不是开放式大型对战平台。反向代理日志应避免记录 /api/events 的查询参数（其中有短期席位令牌），请不要分享该 URL。

## 与旧 Lite 的关键差别

产兵间隔按固定地图尺寸(size)插值，不按当前能量；100是产兵软上限，增援可超过100；敌方脂肪罩还会使能量衰减；特殊细胞也计入胜负；抗体感染保留特殊电池能量。

**帧率说明：**模拟使用原始SWF的25fps，240/360帧对应9.6/14.4秒。完整数值、出处与历史对齐审计见[PORTING.md](PORTING.md)；本轮稳定性修复和批量模拟结果见[BUGSWEEP.md](BUGSWEEP.md)。

## 分层

- src/core.js：纯逻辑、固定25fps、种子随机、单位和mini碰撞；不接触DOM。
- src/levels.js：地图注册表和初始数据。
- src/ai.js：原版Normal优先级，只经公共派兵接口下单。
- src/render.js：只读Canvas；保持世界空间比例，窗口不会改变模拟数值。
- src/input.js：选取和Pointer适配。
- src/app.js：DOM、生命周期、计时器装配。
- src/net-client.js：联机传输、房间面板、标签页重连；通过 input/app 适配接口接入。
- server.js：静态白名单、房间生命周期、身份验证、权威 core 模拟和 SSE；无运行时依赖。
